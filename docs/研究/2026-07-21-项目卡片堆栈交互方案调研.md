# 项目卡片“点击置前”堆栈交互方案调研

## 结论

**可实现，且首版建议保持纯 CSS + React 状态，不新增动画依赖。**

这个交互本质上是小规模、有固定结构的“循环队列”：页面只需维护项目 `id` 的显示顺序；最后一个项目为展开的当前卡片，前面的项目只显示标题条。点击任一标题条后，把它从原位取出并追加到数组末尾，原展开卡自然移动到前一张标题条的位置。项目实体本身、后台的 `sortOrder` 与发布数据不应被这次访客侧交互改写。

对当前 Next.js 14、React 18、纯 CSS 项目，这条路径最小、最可控，已足以得到示意图中的“书签/堆栈”效果。

## 与现有项目的匹配

- 当前访问页的 `components/ProjectCases.tsx` 已经是 `"use client"` 组件，项目清单也以 `project.id` 为 React key；它正适合承担仅在浏览器内发生的顺序状态。
- 当前 `package.json` 没有动画库。新增库会进入该客户端组件所在的前端 bundle。Next.js 官方说明：`"use client"` 边界下被导入的子模块会成为客户端 bundle 的一部分；因此不为这一处小交互引入库更符合本站轻量目标。[1]
- 这不是拖拽排序、手势跟随、跨页面共享元素或出入场复杂编排；不需要通用动画框架。

## 推荐的原生实现

### 状态与重排

以 API 返回的稳定项目 `id` 初始化 `order: string[]`，不在渲染期间生成 key。`activate(id)` 的逻辑是：

```ts
setOrder((current) => [...current.filter((itemId) => itemId !== id), id]);
```

按 `order` 映射完整项目实体；数组的最后一项为展开卡，其他项为折叠标题条。React 官方特别指出：会移动、插入或删除的列表应使用稳定 key，让 React 能识别同一实体而不是把数组位置误当身份。[2]

### 布局与过渡

每张卡都保留在堆栈容器中，使用自己的顺序索引设置 CSS 自定义属性（如 `--stack-index`）：

- 折叠卡只渲染/显示标题按钮，固定标题高度（约 48–56px）；
- 展开卡显示现有背景、职责、方案、成果、标签和“向 AI 了解此项目”按钮；
- 同一 `id` 的卡通过 `transform: translateY(...)` 和 `z-index` 到达新的槽位；CSS 对 `transform`、`opacity` 使用约 220–300ms 的 `transition`；
- 激活卡的内容在到达/离开时淡入淡出。容器以展开卡内容的最大/测得高度预留空间，避免下方页面随卡片切换跳动。

CSS transition 正是为“CSS 属性改变时，以可配置缓动而非瞬时变化”的场景设计的。[3] 这里的槽位数量很小，浏览器原生 `transform` 过渡已足够平滑。

### 交互与可访问性边界

- 折叠标题使用原生 `<button type="button">`（不要把不可点击的 `<article>` 绑定点击），提供清晰的 `aria-label`，键盘 Enter/Space 自动可用。
- 当前展开卡的标题不做重复的“置前”操作；卡片数为 1 时退化为现有单卡，不显示无意义的标题堆栈。
- 添加 `@media (prefers-reduced-motion: reduce)`，关闭或显著缩短 `transform` / `opacity` 过渡；用户系统偏好应优先于装饰性动画。
- 不把“访问者当前查看哪张卡”的顺序写回 COS，也不改变管理员的排序号；刷新后回到已发布的标准排序。

## 方案对比

| 方案 | 能力与官方依据 | 对本需求的代价 | 结论 |
| --- | --- | --- | --- |
| React state + CSS transition | React 原生数组状态与稳定 key 即可表达重排；CSS transition 可对属性变更做时间/缓动控制。[2][3] | 无依赖；需要少量明确的槽位、层级和 reduced-motion CSS；只适合本次小型确定交互。 | **首版采用。** |
| Motion（原 Framer Motion）`layout` | 官方文档说明 `layout` 可在 React render 导致的位置/尺寸改变时自动做布局动画，明确覆盖“reordering a list”；动画以 `transform` 实现。[4] | `motion` 常用声明式组件无法进一步 tree-shake 到低于约 34 kB；若需要布局动画，`LazyMotion + domMax` 仍要带布局功能包。Motion 官方给出了首屏约 4.6 kB 的 LazyMotion 最小路径，但 `domMax` 功能包约 +25 kB（原始/压缩口径以其文档为准）。[5] 还需额外客户端组件导入与依赖维护。 | 若后续加入拖拽、跨区 shared layout、卡片频繁增删，作为二期候选；**不为当前交互引入。** |
| Motion `AnimatePresence` | 官方组件用于 React 树中子节点移除时的退出动画，直接子项必须有唯一 key。[6] | 本设计应让所有堆叠卡留在 DOM 里并移动槽位，不需要删除/重新挂载；引入它反而增加复杂度。 | 不使用。 |
| react-spring `useTransition` | 官方文档称它适合“进入/离开数据集或不希望留在 DOM 的元素”，并支持数据数组、keys、`from/enter/leave`；文档还列出 list reordering 示例。[7] | 需要新增 `@react-spring/web`，并由开发者配置每项 spring、生命周期和定位；对单次点击交换的确定动画而言，复杂度高于 CSS。 | 不使用；只有将来需要物理弹簧、手势驱动或复杂编排才复评。 |

## 是否存在可直接采用的“现成一方组件”

**没有。** Motion 官方提供的是 `motion`、`layout`、`AnimatePresence` 等通用动画原语，并非可直接满足“顶部只露标题、点击移至最前”的成品 Card Stack；react-spring 官方提供 `useTransition` 等 hooks，同样不是项目卡片组件。[4][6][7]

shadcn/ui 的 Card / Badge 是视觉基础组件，也不包含该堆栈行为。即使采用其视觉结构，顺序状态、标题条和置前规则仍须由本项目实现。因此不建议为了“找现成组件”引入来源不明的第三方 Card Stack；它们往往绑定 Tailwind、手势库或不同的可访问性/SSR 假设，和当前纯 CSS 站点不匹配。

## 建议的验收与实现顺序

1. 为 `ProjectCases` 增加客户端 `order`，保持 API/持久化模型不变；项目数 `0/1/2/3+` 都有明确布局。
2. 实现标题条按钮、`activate` 循环重排与稳定 `project.id` key。
3. 添加 CSS 槽位动画、当前卡内容过渡、窄屏单列尺寸与 reduced-motion 回退。
4. 测试：点击任一折叠卡后它成为展开卡；旧展开卡回到折叠条；顺序不写回服务端；键盘激活可用；单卡无堆栈；`prefers-reduced-motion` 时没有运动依赖。
5. 真机检查卡片内容高度不同的情形；若容器高度跳动明显，再用 `ResizeObserver` 在客户端记录当前展开内容高度，而不是先引入动画库。
