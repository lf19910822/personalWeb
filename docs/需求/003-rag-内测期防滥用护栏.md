# RAG 内测期防滥用护栏

## 背景与目标

本站的 RAG 聊天会产生 embedding 与大模型回答成本。现有的单实例内存限流只能降低低频滥用，不能约束超长输入、并发流式连接、日成本或绕过网页门禁直接调用 API 的行为。

本需求为**内测阶段**建立可观察、可控成本的访客聊天护栏。目标是在不引入 Redis 或 CAPTCHA 的前提下，保护 Qwen 调用额度并向访客提供可理解的失败反馈。公开上线前再将易失的内存状态迁移至 Redis，并评估 WAF / CAPTCHA。

## 适用范围与术语

- **访客聊天**：由非管理员经 `/api/chat` 发起的 RAG 查询、查询 embedding 与回答生成。
- **每日访客聊天预算**：按北京时间聚合的访客聊天成本上限；包含查询 embedding 与模型回答，不包括管理员上传文档时的 embedding。
- **预算预留**：请求开始前按最坏可能成本占用的额度；请求结束后以模型实际 Token 用量结算，释放未使用的差额。
- **签名访客 Cookie**：完成门禁后由服务端签发、可校验的聊天权限凭据；它不携带访客问题内容。
- **护栏拒绝事件**：按错误类型聚合的拒绝计数，不记录问题正文、IP 或访客身份。

## 已确认的产品决定

### 访客权限与身份边界

- `/api/chat` 必须验证签名访客 Cookie；不能再因 API 路径被中间件跳过而绕过门禁。
- 完成现有访客门禁后签发签名 Cookie，有效期 30 天。
- Cookie 使用 `HttpOnly`、`SameSite=Lax`；生产环境启用 `Secure`。
- 内测阶段不加入 CAPTCHA / 人机验证。
- API 的 IP 限流只能使用由部署平台代理清洗后的客户端 IP；不得盲目信任用户可伪造的转发头。

### 成本、配额与并发

- 每日访客聊天预算为 **¥5**，按 `Asia/Shanghai` 每日 00:00 重置。
- 每次访客聊天的 query embedding 与模型回答都计入该预算。
- 管理员上传 / 更新 RAG 文档产生的 embedding 单独记账，不占访客聊天预算。
- 单个签名访客上限为 **3 次/分钟**、**20 次/天**。
- 单个 IP 上限为 **10 次/分钟**，用于防止反复创建 Cookie 的突发请求。
- 全站同时最多 **5 个**正在生成的访客聊天请求；超过时立即拒绝，不排队。
- 每次请求开始前，按 query embedding 加 **1,500 输出 Token** 的最坏可能费用预留预算；完成后按模型返回的实际 Token 用量结算并释放差额。
- 访客断开 SSE 连接时，服务端立即中止上游 Qwen 请求并释放并发名额。若无法取得最终用量，保守保留该次预算预留。
- 单次上游 RAG 调用最长 **60 秒**；超时后中止请求并释放并发名额。

### 输入、输出与回答截断

- `question` 最多 2,000 个字符。
- 历史消息仍最多保留最近 4 条；每条内容最多 1,000 个字符。
- 模型请求显式设置最大输出为 **1,500 Token**。
- 系统提示词要求优先简洁、分点回答。
- 当上游返回 `finish_reason = length` 时，不自动续写；前端在答案末尾提示访客将问题拆分后继续追问。
- 前端不自动重试超时或上游不可用的请求；只显示可理解提示，由访客主动再次发送。

### 前端错误类型与反馈

- 聊天 API 对 JSON 响应和 SSE 错误事件返回稳定的机器可读错误码，前端据此显示友好文案。
- 至少区分：
  - 未通过访客验证；
  - 输入无效或过长；
  - 访客短时限流；
  - IP 短时限流；
  - 访客当日次数耗尽；
  - 全站并发已满；
  - 当日访客聊天预算耗尽；
  - 上游超时；
  - 上游暂不可用；
  - 回答达到输出长度上限（非失败，作为完成状态元数据）。
- 不把 Qwen 的原始错误、预算数值、精确剩余次数或内部实现暴露给访客。
- 访客提示应提供下一步动作，例如“请稍后重试”“请明日再来”或“请将问题拆分后继续追问”。

### 后台可见性与紧急预算追加

- 后台“AI 配置”展示：
  - 今日访客聊天预算的已用、预留、剩余与总额度；
  - 今日访客聊天次数；
  - 当前正在生成的聊天数；
  - 最近一次护栏拒绝原因；
  - 今日预算追加次数与累计追加金额。
- 后台提供“为今日访客聊天预算追加 ¥5”的操作。
- 预算追加次数不设上限，但每次都必须二次确认；确认弹窗显示“今日已追加 X 次 / 已增加 ¥Y”。
- 追加操作只增加当天可用总额度，不篡改已经发生的实际成本。
- 追加操作记录时间、金额与管理员账号，保留 30 天。
- 护栏拒绝事件只按日聚合错误类型计数，保留 30 天；不保存问题正文、IP 或访客身份。

### 配置与内测存储策略

- 所有阈值使用环境变量配置，并提供安全默认值；后台不直接编辑这些阈值。
- 环境变量至少覆盖：每日预算、每次预算追加金额、访客 / IP 分钟限额、访客日限额、全站并发、请求超时、问题长度、历史消息长度、最大输出 Token、Cookie 有效期。
- 内测阶段使用进程内存保存分钟限流、访客日限额、并发和预算预留；服务重启后这些状态会清零。
- 每日实际用量、预算追加审计与拒绝事件聚合通过现有对象存储抽象持久化，因此 ¥5 日预算在重启后仍然有效。
- 公开上线前必须用 Redis 替换上述内存状态，以支持多实例与重启恢复。

## 数据与权限边界

- 访客聊天预算只针对公共聊天，不限制管理员上传文档的 embedding。
- 管理员预算追加 API 必须沿用现有管理员认证，并记录操作管理员账号。
- 用量账本、拒绝事件和预算追加审计不得记录访客问题正文、RAG 文档正文、IP 或可识别访客身份。
- 内测期的签名 Cookie 只用于聊天权限与配额关联，不作为访客画像或分析数据来源。

## 非目标

- 内测阶段不接入 Redis、CAPTCHA、WAF 或付费人机验证服务。
- 不提供全站预算重置或全站临时放行按钮。
- 不提供指定 HR 的优先链接 / 免限额链接。
- 不让前端显示精确的访客剩余次数、全站剩余预算或内部错误详情。
- 不自动续写被 Token 上限截断的回答，也不自动重试上游失败。

## 验收标准

1. 未携带有效签名访客 Cookie 的 `/api/chat` 请求被拒绝，网页门禁完成后可正常提问。
2. 访客聊天在 3 次/分钟、20 次/天或同 IP 10 次/分钟任一限制触发时返回对应稳定错误码与友好前端提示。
3. 问题超过 2,000 字符，或任一保留历史消息超过 1,000 字符时，请求在调用 embedding / 模型前被拒绝。
4. 单次回答最多生成 1,500 Token；若达到输出上限，前端提示回答未自动续写且可继续追问。
5. 同时第 6 个访客聊天请求立即被拒绝；任一请求超过 60 秒或访客断开时，上游请求中止并释放并发名额。
6. 访客请求的 embedding 与回答成本均计入当天 ¥5 预算；管理员文档 embedding 不占该预算。
7. 并发请求通过预算预留不能共同穿透当天额度；正常结束后按实际 Token 费用释放预留差额。
8. 预算耗尽后，访客获得不含精确余额的提示；管理员可经过确认为当天追加 ¥5，且弹窗与状态均显示今日累计追加次数和金额。
9. 后台显示今日预算、预留、剩余、访客聊天次数、当前并发、最近拒绝原因与预算追加信息。
10. 拒绝事件和预算追加审计在 30 天内可按日查看，且不包含问题正文、IP 或访客身份。
11. 内测重启后分钟限流、访客日限额、并发与预留可清零，但当天已发生费用与预算追加仍会影响当天可用预算。
12. 所有护栏阈值可由环境变量覆盖；公开上线前的实现任务明确包含 Redis 替换内存状态。
