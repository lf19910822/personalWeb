# 公开项目卡片与求职转化

## 背景与目标

本站的首要目标是促成招聘方行动：快速判断候选人的能力、查看简历，并通过 AI 助手了解项目细节。当前页面有工作经历和 AI 问答，但缺少可快速验证影响力的公开项目案例。

本需求新增可由管理员维护的“公开项目卡片”。项目卡片与 RAG 文档是不同的内容实体：RAG 用于问答知识边界，项目卡片用于经过人工编辑与发布的对外展示。个人经历、校园经历或其他 RAG 文档不得自动出现在访问页。

## 已确认的产品决定

### 首页转化顺序

- 首屏维持现有顺序：主行动为“查看个人简历 PDF”，次行动为“向 AI 提问”。
- 不将“联系我”替换为首屏次行动。
- AI 助手用于回答访客对经历和项目的深入追问。

### 公开项目列表

- 访问页新增独立的“项目案例”区，位于工作经历之后、AI 助手之前。
- 侧栏新增“项目案例”导航项，支持直接跳转到该区。
- 页面采用可扩展的项目列表布局；当前即使只有一张卡片也按列表呈现。
- 当已发布项目多于一张时，列表以“书签式堆栈”展示：上层卡片只显示项目名称，最下方卡片完整展开。
- 点击任一上层项目名称，会将该项目移动到展开位，原展开卡回到标题条位置。这个顺序仅保留在访客当前浏览器，不写回 COS、不改变后台排序号；刷新后恢复管理员设置的标准排序。
- 卡片从标题条移动到展开位时应有平滑的下移与内容淡入过渡；点击标题条后，页面以约 500ms 的三次方缓入缓出曲线滚动到新的展开卡，确保访客立即看到展示结果。自动滚动期间暂时阻止鼠标滚轮，避免与动画抢占；再次点击时取消尚未完成的滚动并恢复输入，以最新选择为准。
- 动画仅由站内“减少动态效果”开关控制；默认播放动画，不读取或覆盖访客操作系统的“减少动态效果”偏好。
- 项目只有一张时退化为普通完整卡片，不显示无意义的堆栈标题条。
- 当前 COS 持久化索引中只有 `Cost Hub 多源成本数据平台技术复盘` 一份项目文档；首个公开卡片由管理员据此手工创建。
- 不自动将 RAG 文档转换为项目卡片，也不在访问页公开 RAG 正文。

### 项目卡内容与交互

每张项目卡使用结构化文字内容，不支持图片、富文本或独立详情页。固定字段为：

- 项目名称
- 一句话简介
- 项目背景 / 问题
- 我的职责
- 关键方案，最多 3 条
- 成果数据，最多 3 条
- 技术标签
- 排序号
- 可选关联的 RAG 文档标识

项目卡提供“向 AI 了解此项目”按钮。点击后滚动到 AI 助手，并预填针对该项目的提问；访客可修改问题后再发送。可选关联的 RAG 文档只用于这项 AI 追问的上下文引导，不会公开其原文。

### 后台管理与发布

- 后台新增“项目”管理页，可新增、编辑、排序、取消发布和永久删除项目卡片。
- 新建卡片默认是草稿，不会出现在访问页。
- 只有点击“发布”后的卡片才会在访问页显示；编辑已发布卡片后必须再次发布才覆盖线上版本。
- “取消发布”会立即从访问页隐藏卡片，但保留其草稿内容。
- “永久删除”需要二次确认。
- 编辑内容由管理员决定，系统不从 RAG 文档自动覆盖或补写公开文案。

## 数据与权限边界

- 项目卡片与其发布状态应通过现有对象存储抽象持久化：配置 COS 时保存到私有 COS；本地开发时降级到 `data/objects/`。
- 项目管理 API 必须沿用现有管理员认证；访问页仅可读取已发布卡片。
- 关联 RAG 文档时仅列出文档标识和标题，不能向访客返回文档正文。

## 非目标

- 不自动识别“项目类”RAG 文档。
- 不创建项目详情页、封面图上传、富文本编辑器或评论功能。
- 不将草稿、已取消发布项目或 RAG 文档正文暴露给访问页。
- 不在本需求中实现模型提供商的真实切换功能。

## 验收标准

1. 管理员能创建一张 Cost Hub 草稿卡，并填写全部固定字段和可选 RAG 文档关联。
2. 草稿不会出现在访问页；发布后会出现在“项目案例”区；取消发布后立即消失。
3. 访问页只返回已发布项目，并按排序号稳定排序。
4. 卡片的“向 AI 了解此项目”按钮会定位到 AI 助手并预填项目问题。
5. 管理员可永久删除项目，删除前必须确认；删除后前后端均不可再读取该卡片。
6. RAG 中新增个人经历、校园经历或其他非项目资料后，不会自动出现在项目列表。
