# RAG Markdown 摄取、父子检索与用量统计

个人站的 RAG 从文本框上传和临时分块，演进为可持久化管理的 Markdown 文档库。选择父子切分而非仅按空行或固定长度切分：子块提升相似度检索精度，父块保留完整章节语境；同时在不引入独立向量数据库或 Grafana 的前提下，保留低流量个人站所需的成本可见性。

## 已接受的决策

### 文档摄取与身份

- 管理员仅可上传 `.md` 文件，Markdown 完全替代粘贴文本。
- 元数据优先读取 YAML front matter 的 `title`、`description`；缺失时依次回退到第一个一级标题、首个正文段落和文件名。
- 文件名是**文档标识**。同名文件表示更新，成功后替换该文档的全部父块、子块和向量；使用新文件名才会新增文档。
- 支持批量上传；同一批次出现重复文件名时，预检直接拒绝该批次，避免顺序覆盖。
- 每批最多 20 个文件，单文件不超过 256KB，总计不超过 1MB。确认后按文件顺序处理。
- 删除是永久删除：移除文档、父块、子块和向量，并在后台二次确认。

### 预检与原子性

- 上传先进行本地预检，展示每份文件的元数据、父块/子块数量、预估 embedding Token 和预估费用；管理员确认后才调用模型并写入持久化索引。
- 预检使用保守本地估算，明确标记为“预计”；完成调用后以接口返回的实际 Token 记账。
- 批量导入按单文档原子性处理：成功文件立即保留；失败文件不新增、不覆盖旧版本，报告原因并允许单独重试。失败不回滚同批其他成功文件，也不保留半成品文档。

### 父子切分与检索

- 以 Markdown 标题层级为结构边界，优先保留代码块和表格的完整性。
- 二级标题章节形成父块；超过约 1,200 Token 的父块再按结构拆分。
- 父块派生约 350 Token 的子块，相邻子块保留约 60 Token 重叠。
- 只为子块生成 embedding。查询时检索最多 6 个子块，反查、去重后最多向回答模型提供 2 个父块。
- 标题路径作为父块/子块的上下文元数据，避免小块脱离所属项目或经历章节。

### 持久化语料边界

- COS 中的持久化索引是首次建立后的唯一语料来源。
- `data/corpus.json` 只用于 COS 尚无索引时的首次初始化；之后不会自动合并或覆盖 COS 中的文档。
- 删除文档不删除用量账本，因为已发生的 Token 与费用应保留为真实的历史成本。

### 用量与费用可见性

- 用量账本按日聚合，不保存问题正文、文档正文、访客身份或 IP。
- 分别记录 chat 与 embedding 的请求次数、输入 Token、输出 Token（适用时）和估算费用。
- 后台显示累计概览、最近 30 天日趋势，并区分 chat 与 embedding。
- 图表使用原生 SVG/CSS，不引入 Chart.js、ECharts、Grafana 或 Grafana 数据源。
- 模型单价维护在可版本管理的 `config/rag-pricing.ts`；费用是估算值，百炼账单仍为最终依据。

### 文档编写指南

- 在 `docs/` 提供 RAG 文档编写指南，包含 Markdown 规范、front matter、标题层级、内容边界与完整模板。
- 同一指南提供可直接交给 Codex 的生成指令；Codex 只能依据给定原始材料生成文档，不得补写经历、项目事实或量化成果。

## 考虑过但不采用的方案

- 保留文本框与 Markdown 两套上传入口：会产生内容来源不一致，故不采用。
- 仅用固定长度重叠切分：检索与回答使用同一小块，容易丢失章节语境，故不采用。
- 独立向量数据库或 Grafana：当前个人站的文档量、调用量和运维需求不足以抵消新增服务的复杂度，故暂不采用。

## 后果

- Markdown 文件名成为稳定接口，重命名会被视为新增文档而非更新。
- 父块可能比子块消耗更多回答上下文，因此严格限制回传父块数量。
- 模型价格变化需要维护单价配置；后台费用必须标明“估算”。
